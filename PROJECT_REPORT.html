01 Executive Summary

MARK XLIX is a JARVIS-style desktop voice assistant. Instead of a wake-and-respond chatbot, it maintains an always-on Gemini Live audio session: the microphone streams continuously, the assistant's voice answers with ultra-low latency, and a library of 22 voice-invokable tools gives it real control over the machine — launching apps, controlling browsers, managing files, checking hardware telemetry, setting reminders, searching the web, and even reading the screen through live vision.

The build philosophy of XLIX is personalization & autonomy: it learns your name, remembers long-term facts, starts itself on boot, watches the clipboard, and adapts to the language you speak. The next milestone (Mark L) adds wake-word, a smarter proactive system, and daily session memory.

02 Architecture

Runtime Flow

1 · Boot — main.py loads config + long-term memory, builds a Gemini LiveConnectConfig (system prompt, identity injection, current date/time, tool declarations), then opens the streaming session with voice Charon.

2 · Listen — sounddevice captures 16 kHz int16 PCM in a callback thread; the HUD VU meter is fed via strided RMS while frames are pushed into an asyncio out-queue.

3 · Think — The model may emit FunctionCalls. JarvisLive._execute_tool() dispatches them to the matching actions/* module in a thread executor, and returns FunctionResponse.

4 · Speak — 24 kHz audio streams back and is chunked into ~50 ms slices so the interrupt button stops speech within 50 ms; transcripts are logged to the HUD and mirrored to the phone dashboard.

5 · Vision — screen_process captures the screen/webcam, compresses to JPEG (≤1280×720), and injects the image into the live session for analysis. A 4 s cooldown prevents echo-triggered duplicate captures.

6 · Remember — save_memory silently persists personal facts (identity, preferences, projects, relationships, wishes, notes) to memory/long_term.json, which is injected into every future prompt.

Key Design Decisions

50 ms interrupt slicing
Received audio is split into 2400-byte chunks so the interrupt handler can discard queued audio and re-open the mic almost instantly.
Nuclear subprocess guard
On Windows, Popen is globally patched to force CREATE_NO_WINDOW — no console flashes from any tool.
Vision cooldown
A 4 s monotonic cooldown + busy-flag prevents the model's echo from triggering duplicate screen captures.
Two-phase briefing
News is pre-fetched in a background thread while the greeting plays — no extra Gemini round-trip at startup.
Identity injection
Assistant name, user name and current date/time are injected into the system prompt every session — prompt.txt stays static.
Local LLM fallback
core/llm_client.py supports Ollama / LM Studio backends with KV-cache warmup (≈17 s → <1 s first-token).

04 Memory System

Persistent facts live in memory/long_term.json and are injected into every system prompt. Memory is auto-trimmed (oldest-first by updated date) to a ~2.2 KB budget, and values are capped at 380 chars.

identity
name, age, birthday, city, job, language, nationality…
preferences
favorite food / color / music, hobbies…
projects
active projects, goals, things being built
relationships
friends, family, partner, colleagues
wishes
future plans, things to buy, travel dreams
notes
habits, schedule, anything else worth remembering

✏️ remember() / forget() helpers are also exposed for programmatic access. Settings (API key, assistant name, user name, wake word, briefing toggle) are stored separately in config/api_keys.json.

05 Development Status

Test Coverage

tests/test_regressions.py crash regressions

Guards the F821 undefined-name bugs found by a ruff pass — subprocess in _focus_window, vision constants in screen_processor, undefined _get_model() in dev_agent. Also enforces argument-list (non-shell) subprocess calls on every OS branch and cross-OS focus-window behavior.

tests/test_ui_features.py UI / headless

Tests _lerp_hex color morphing, command-history line edit (Up/Down navigation, 50-cap, draft restore), the HUD VU meter (peak-hold + decay), and the help overlay — with a live 16 ms animation-timer test via QTest.qWait.

tests/test_wake_word.py audio / mocked

Covers the WakeWordDetector: lifecycle (start/stop/pause/resume), energy-VAD triggering, Porcupine mode (keyword/sensitivity/cleanup), and robustness edge cases — mic fully mocked.

test_gallery.py · test_image_generation.py features

Standalone suites for the generate-all-styles gallery and image-generation pipeline.

Health & Observations

  • Well-tested core — the crash-level regressions (vision pipeline, window focus, dev agent) are locked down with tests; UI animation is exercised headlessly.
  • Security hygiene — subprocess calls use argument lists (no shell=True), and Windows console windows are suppressed globally.
  • Not a git repository — .gitignore exists but the folder has no .git/; history / version control is not set up.
  • Heavy dependency footprint — torch, faster-whisper and playwright/Chromium make first install large (~GB scale); core/installer.py and the README both auto/ manually handle missing packages.
  • Optional extras — pvporcupine (accurate offline wake word) and some Windows packages are optional / platform-gated.
  • Version pin note — kokoro>=0.9 is pinned because 0.9 dropped AlbertModel/AutoModel support.
